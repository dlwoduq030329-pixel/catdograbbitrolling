# Renew 전투 개발 인수인계

기준일: 2026-08-13

## 이 폴더를 읽는 순서

1. `00_먼저_읽어주세요.md`: 현재 구조와 핵심 원칙
2. `01_폴더별_코드_설명.md`: 각 폴더와 주요 스크립트의 역할
3. `02_전투_흐름과_데이터_참조.md`: 실행 순서와 데이터 연결
4. `03_현재_개발단계_QA.md`: 완료·보류·검증할 항목
5. `04_협업_규칙과_주의사항.md`: 수정 경계와 리뷰 규칙
6. `카드_데이터_및_구현현황.xlsx`: 카드 0~27 데이터와 효과·구현 상태

## 현재 전투 한 줄 요약

`BattleGameManager`가 턴을 진행하고, `BattleDataPool`과 Registry가 런타임 참조를 공유하며, Player·Enemy·Card·UI 기능은 폴더별 서비스와 컨트롤러로 분리되어 있다.

## 반드시 지킬 경계

- `Assets/renew/Scripts_map`: 맵 시스템 원본 영역이다. 호환 코드는 Battle 쪽에 작성하고 임의 수정하지 않는다.
- `Assets/renew/share`: 공용 UI와 레거시 데이터 연결 영역이다. 기존 동작을 보존하고 필요한 경우 어댑터를 Battle 쪽에 둔다.
- `Assets/Game`: 카드 이미지·상점·VFX 등 레거시 원본 자산이다. 원본을 직접 고치기보다 Battle Reference/Bridge를 사용한다.
- Public API는 리뷰 없이 이름이나 시그니처를 바꾸지 않는다.
- 컴파일 성공만으로 완료 처리하지 않는다. 반드시 Moon Scene Play Mode 주요 흐름을 확인한다.

## 현재 핵심 플레이 흐름

캐릭터 선택 → 카메라 이동 완료 → Battle Canvas 활성화 → 주사위 → Player 선택 → 이동/공격/카드 → Confirm 또는 Quit → 턴 종료 → Enemy 행동 → Player 턴 복귀

## 데이터의 기준

- 카드 이미지·원본 MP·레거시 번호: `Battle/CardData/Legacy/CardDatabaseLegacy.asset`
- 실제 전투 대상·사거리·효과 실행 데이터: `Battle/CardData/PlayerCardMain.asset`
- 카드 28장 기획 기준표: `Battle/CardData/BattleCardMasterDatabase.asset`
- Enemy 정적 데이터: `Battle/Data/BattleEnemyDatabase`
- Player 런타임 데이터: `Battle/Player/BattlePlayerRuntimeDataFactory`가 스폰 시 구성

현재 카드 런타임의 최종 기준은 `PlayerCardMain.asset`이다. Master Database는 기획·검토용이며 자동 실행 기준이 아니다.
