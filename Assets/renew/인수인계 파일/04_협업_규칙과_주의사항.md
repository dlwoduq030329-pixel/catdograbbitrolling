# 협업 규칙과 주의사항

## 역할 원칙

- 미확정 설계는 임의로 확정하지 않고 검토 항목으로 기록한다.
- 한 번에 하나의 책임 범위를 수정한다.
- 병렬 작업은 서로 다른 영역을 담당하고, 관련 코드를 교차 확인하여 호환성을 보장한다.
- 중복 구현을 발견하면 새 코드를 추가하기 전에 기존 진입점과 데이터 소유자를 정한다.
- 모든 수정은 Play Mode에서 검증한다.

## 수정 전 확인

1. 수정할 기능의 데이터 소유자가 누구인지 확인한다.
2. `Scripts_map`, `share`, `Assets/Game` 원본을 변경해야 하는지 먼저 검토한다.
3. Battle Bridge 또는 Reference로 해결할 수 있으면 원본을 수정하지 않는다.
4. Public API 사용처를 `rg`로 모두 찾는다.
5. 기존 QA 재현 방법을 읽는다.

## 수정 후 완료 조건

- C# 정적 컴파일 오류 0개
- Moon Scene 주요 사용자 흐름 Play Mode 확인
- 범위 레이어와 UI 입력 충돌 확인
- 데이터 인덱스·MP·이미지 호환 확인
- `Docs/BATTLE_BUG_QA_LOG.md` 업데이트
- 기술 부채가 생기면 ID, 이유, 우선순위, 상태, 목표 버전을 기록

## 금지 사항

- 검토 없이 Singleton 추가
- Controller가 새 데이터 저장소 역할까지 겸하도록 확장
- 카드 인덱스 대신 Button 배열 위치를 데이터 ID로 사용
- 효과 실행 전에 MP를 먼저 차감
- 카드·이동 취소 시 레이어만 숨기고 행동 상태를 남김
- 레거시 AnimationEvent에서 Battle 피해를 중복 적용
- 원본 프리팹을 복제한 뒤 출처와 갱신 방법을 기록하지 않음

## 인수인계 문서 갱신

- 기능 추가·버그 수정·데이터 변경·QA 완료 시 `인수인계 파일`의 관련 문서를 같은 작업에서 갱신한다.
- 카드 데이터가 변경되면 `카드_데이터_및_구현현황.xlsx`의 카드 현황과 QA 상태를 함께 갱신한다.
- 폴더 또는 주요 스크립트가 추가·삭제·이동되면 `01_폴더별_코드_설명.md`를 갱신한다.
- 실행 흐름이나 데이터 소유권이 바뀌면 `02_전투_흐름과_데이터_참조.md`를 갱신한다.
- 구현 단계와 QA 결과가 바뀌면 `03_현재_개발단계_QA.md`를 갱신한다.
- 문서에는 기능, 구조, 검증 결과와 기술 부채만 기록한다. 대화체, 개인 평가, 작업 도구 이름은 기록하지 않는다.
